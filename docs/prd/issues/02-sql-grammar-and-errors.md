# 02: SQL 문법 전체와 오류 메시지

**What to build:** 팀원이 합의한 SQL 범위 전체를 CLI로 쓸 수 있습니다. field 목록과 `WHERE field = 값`으로 record를 고르고, 틀린 문장은 몇 번째 줄에서 무엇이 틀렸는지 오류로 받습니다. SQL 파일은 첫 오류에서 멈춥니다. 100만 건 적재를 위해 `-q`로 INSERT 결과 출력을 끌 수 있습니다. 결정은 `docs/prd/final.md` Phase 1 절의 파서, 어휘 규칙, INSERT, SELECT, 실행 순서, 타입, CLI를 따릅니다.

**Blocked by:** 01

**Status:** ready-for-agent

작업에 포함되는 것:

- **어휘 규칙**: 키워드는 대소문자를 구분하지 않고, 테이블과 field 이름은 구분합니다. 문자열 안의 작은따옴표는 `''`로 적습니다(`'O''Brien'`). 모든 문장은 `;`로 끝나고, 문자열 안의 `;`는 문장을 끝내지 않습니다. `--` 같은 주석은 지원하지 않으므로 문법 오류입니다.
- **문법**: `SELECT (* 또는 field 목록) FROM 테이블 [WHERE field = 값];`입니다. WHERE는 field 하나와 `=` 하나입니다.
- **파서 오류**: 토큰마다 줄과 칸 위치를 담습니다. 문법 오류는 줄 번호와 기대한 토큰을 알립니다. 예: `2번째 줄: VALUES 다음에 '('가 와야 합니다`.
- **검증 → 실행**: 실행 전에 테이블과 field가 있는지, 값 개수와 타입이 스키마와 맞는지 확인합니다. `id`를 포함해 값을 하나 더 적으면 값 개수 오류입니다. `INT`는 64비트 부호 있는 정수이고 범위를 넘는 숫자는 오류입니다. `TEXT` 값은 1 MiB를 넘으면 오류입니다. `WHERE id = 'abc'`와 `WHERE age = 'x'`는 타입 오류이며 SCAN으로 넘어가지 않습니다. 이 티켓의 접근 경로는 언제나 SCAN입니다.
- **CLI**: 첫 오류에서 멈추고 위치와 이유를 stderr에 씁니다. 그 앞에서 성공한 INSERT는 파일에 남습니다. SQL 파일에 NUL 바이트가 있으면 입력 오류(종료 코드 1)입니다. `-q`는 INSERT의 메타 줄을 끕니다.
- **메타 줄**: 문장마다 stderr에 한 줄을 씁니다. INSERT는 `-- 1 record inserted, id 3`, SELECT는 `-- 2 records, SCAN, examined 5, 0.02 ms` 모양입니다. 티켓 07이 INDEX 값을 더합니다.
- **문서**: `README.md`의 "알려진 한계"에 두 줄을 더합니다. "CLI가 오류에서 멈춰도 그 앞의 INSERT는 남는다", "우리 `INT`는 64비트이고 PostgreSQL·MySQL의 `INT`(32비트)와 다르다". 스키마 설명에도 `INT` 크기를 적습니다. `docs/requirements.md`의 L9, L35, L47 행을 채웁니다.

완료 조건 (테스트 이름은 한국어 문장으로 씁니다):

- [ ] `select`, `SELECT`, `SeLeCt`가 같게 동작하고, 테이블 이름의 대소문자가 다르면 없는 테이블 오류입니다.
- [ ] `'O''Brien'`과 `'a;b'`가 값 그대로 저장되고 조회됩니다.
- [ ] field 목록 SELECT가 요청한 field만 그 순서로 돌려줍니다.
- [ ] `WHERE`로 거른 결과가 맞고, 맞는 record가 없으면 0건입니다.
- [ ] 마지막 `;`가 빠진 파일, 닫히지 않은 문자열, `--` 주석은 줄 번호가 있는 문법 오류입니다.
- [ ] 없는 테이블, 없는 field, 값 개수 불일치, 타입 불일치, 64비트를 넘는 숫자, 1 MiB를 넘는 `TEXT`가 각각 구분되는 오류입니다.
- [ ] 세 번째 문장이 틀린 파일은 앞의 INSERT 두 개를 남기고 네 번째 문장을 실행하지 않습니다.
- [ ] NUL 바이트가 든 SQL 파일은 종료 코드 1입니다.
- [ ] `-q`를 주면 INSERT 메타 줄이 나오지 않고, SELECT 결과는 그대로 나옵니다.
