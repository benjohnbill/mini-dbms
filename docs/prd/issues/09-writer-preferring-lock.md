# 09: 쓰기 우선 잠금과 여러 스레드의 엔진 사용

**What to build:** 여러 스레드가 같은 엔진을 동시에 불러도 데이터가 깨지지 않습니다. 같은 테이블의 SELECT끼리는 동시에 읽고, INSERT는 하나씩 쓰며, INSERT가 기다리기 시작하면 새 SELECT는 기다립니다(쓰기 우선). 잠금은 mutex와 조건 변수로 직접 만들어 macOS와 Linux에서 같게 동작합니다. 결정은 `docs/prd/final.md` Phase 3 절의 동시성과 읽기 위치를 따릅니다.

**Blocked by:** 05

**Status:** done

작업에 포함되는 것:

- **잠금 모듈**: mutex 하나, 조건 변수 두 개, 지금 읽는 스레드 수, 기다리는 쓰기 수, 쓰는 중 여부로 만든 읽기·쓰기 잠금입니다. 읽기는 쓰는 중이거나 기다리는 쓰기가 있으면 기다립니다. 쓰기는 쓰는 중이거나 읽는 스레드가 있으면 기다립니다. glibc 전용 설정은 쓰지 않습니다. 엔진 없이 단위 테스트합니다.
- **엔진에 연결**: 테이블마다 잠금 하나를 둡니다. 토크나이저, 파서, 검증은 잠금 밖에서 하고, 실행 단계에서만 잠금을 쥡니다. SELECT는 읽기 잠금, INSERT는 쓰기 잠금입니다. ID 발급, 파일 쓰기, 트리 등록, 실패 시 되돌리기는 모두 같은 쓰기 잠금 안에서 합니다. 엔진 안에서 잠금을 다시 잡는 경로는 두지 않습니다. 티켓 07이 먼저 끝났든 아니든, 잠금이 실행 단계 전체를 감싸므로 트리 삽입도 쓰기 잠금 안에 들어갑니다.
- **읽기 위치**: SCAN도 `pread`로 읽어, 읽기 잠금을 같이 쥔 스레드끼리 파일 위치를 바꾸지 않습니다. 공유 `FILE *`와 `fseek`은 쓰지 않습니다.
- **`make tsan`**: ThreadSanitizer 빌드로 동시성 테스트를 돌리는 대상을 만들고 CI에서도 돌립니다.
- **문서**: `docs/requirements.md`의 L42 행을 채웁니다.

완료 조건:

- [ ] 잠금 단위 테스트: 읽기 두 개가 동시에 들어갑니다. 쓰기는 혼자만 들어갑니다. 쓰기가 기다리는 동안 새 읽기는 들어가지 못합니다. 순서는 시간이 아니라 테스트가 쥔 조건 변수로 맞춥니다.
- [ ] 빈 테이블에 스레드 100개가 INSERT를 하나씩 보내면, 받은 ID 집합이 1\~100이고 각 INSERT에 넣은 고유 표식이 그 ID로 다시 조회됩니다.
- [ ] SCAN과 INSERT를 섞어 돌려도 반쯤 쓰인 record가 보이지 않고, 조회한 `id`와 데이터가 넣은 짝과 같습니다.
- [ ] 다른 테이블에 대한 요청은 서로 기다리지 않습니다.
- [ ] 위 테스트가 `make tsan`에서 경고 없이 통과합니다.
