# 03: 재시작, 데이터 폴더 잠금, 잘못된 테이블

**What to build:** CLI를 다시 실행해도 저장한 record가 조회되고 ID가 이어집니다. 한 데이터 폴더를 두 프로세스가 동시에 쓰면 나중 프로세스가 오류로 끝납니다. 한 프로세스가 여러 테이블을 씁니다. 스키마가 틀렸거나 데이터 파일이 없으면 엔진이 시작하지 않고 이유를 알립니다. 사람이 바이너리 테이블 파일을 읽을 수 있도록 `dump` 명령을 둡니다. 결정은 `docs/prd/final.md`의 데이터 폴더 독점, 자동 ID, 스키마 파일, 잘못된 테이블, CLI를 따릅니다.

**Blocked by:** 01

**Status:** done

작업에 포함되는 것:

- **엔진 만들기 순서**: 데이터 폴더의 잠금 파일에 비차단 배타 `flock` → 모든 스키마 파일 읽기 → 테이블 파일마다 처음부터 끝까지 한 번 읽어 다음 ID(가장 큰 `id` + 1)와 `committed_size`를 정함. 이 티켓의 읽기는 정상 파일을 가정합니다. 깨진 파일 판정은 티켓 04가 같은 읽기에 더합니다. 엔진이 만들어진 뒤에는 테이블 목록이 바뀌지 않습니다.
- **잠금**: 이미 잠겨 있으면 "다른 프로세스가 사용 중" 오류로 끝납니다(CLI 종료 코드 1). 잠금은 프로세스가 끝나면 저절로 풀립니다.
- **여러 테이블**: 데이터 폴더의 모든 스키마 파일을 테이블로 올리고, 테이블마다 ID를 따로 셉니다.
- **잘못된 테이블**: 형식이 틀린 스키마 줄(줄 번호와 함께), 같은 field 이름 두 번, 지원하지 않는 타입, 스키마에 적힌 `id`, 짝이 되는 데이터 파일이 없음 중 하나라도 있으면 엔진 만들기가 실패합니다.
- **ID 최댓값**: 다음 ID가 `INT` 최댓값을 넘으면 INSERT가 오류입니다.
- **`dump` 명령**: CLI가 테이블 이름을 받아 그 테이블 파일의 record를 SELECT와 같은 TSV로 출력합니다. 명령 모양은 CLI 인자 규칙(티켓 01)과 맞춰 정합니다.
- **문서**: `docs/requirements.md`의 L18 행에 "여러 테이블"을 더합니다. `README.md`에 `dump` 사용법을 적습니다.

완료 조건:

- [ ] INSERT 세 개를 실행하고 CLI를 다시 실행하면 세 record가 조회되고, 다음 INSERT는 ID 4를 받습니다.
- [ ] 두 테이블에 번갈아 INSERT하면 테이블마다 ID가 1부터 따로 올라갑니다.
- [ ] 첫 프로세스가 잠금을 쥔 동안 같은 데이터 폴더로 시작한 두 번째 프로세스는 종료 코드 1로 끝나고, 첫 프로세스가 끝난 뒤에는 시작됩니다.
- [ ] 스키마 오류 다섯 경우가 각각 엔진 만들기 실패이고, 형식 오류는 줄 번호를 알립니다.
- [ ] 데이터 파일이 없는 테이블이 있으면 엔진 만들기가 실패하고 파일을 만들지 않습니다.
- [ ] 다음 ID가 최댓값을 넘는 테이블에서 INSERT는 오류이고 파일이 바뀌지 않습니다. 테스트는 최댓값 근처의 `id`를 가진 테이블 파일을 직접 만들어 씁니다.
- [ ] `dump` 출력이 같은 테이블의 `SELECT *` 출력과 같습니다.
