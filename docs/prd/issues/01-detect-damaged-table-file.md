# 01: 시작할 때 깨진 테이블 파일을 찾아 멈추기

**Status:** ready-for-agent

**What to build:** 엔진을 만들 때(`engine_create`) 테이블 파일을 처음부터 끝까지 한 번 읽어서, 깨진 레코드가 있으면 시작을 멈추고 파일 이름과 위치를 알립니다. 파일은 고치지 않습니다. 회의(2026-11-16)에서 저장 형식을 길이를 앞에 붙인 바이너리로 정했기 때문에, DA 초안의 "마지막 레코드에 `\n`이 없으면 잘린 것" 규칙(`docs/prd/DA.md` 5.3)은 쓸 수 없습니다. 이 티켓이 그 규칙을 대신합니다. 판정 규칙은 회의에서 AI에게 맡긴 결정입니다. 팀이 다르게 정하면 바꿉니다.

**Blocked by:** None (can start immediately)

## 레코드 모양

정수는 모두 리틀 엔디언입니다.

```text
레코드 = 본문 길이 (u32) + 본문
본문   = id (i64) + 스키마 순서대로 필드 값
INT    = i64
TEXT   = 바이트 길이 (u32) + UTF-8 바이트 (최대 1 MiB)
```

스키마에서 테이블마다 두 값을 계산합니다.

- `min_body` = 8 + 8 × (INT 필드 수) + 4 × (TEXT 필드 수). 모든 TEXT가 빈 문자열일 때입니다.
- `max_body` = `min_body` + 1 MiB × (TEXT 필드 수). 모든 TEXT가 최대 길이일 때입니다.

## 시작할 때 읽는 순서

파일 크기를 `S`, 읽는 위치를 `o = 0`으로 두고 레코드마다 반복합니다.

1. `o == S`이면 끝입니다.
2. `S - o < 4`이면 길이 칸이 잘렸습니다. `잘림`으로 알립니다.
3. 본문 길이를 읽습니다. `min_body`보다 작거나 `max_body`보다 크면 `손상`으로 알립니다.
4. `o + 4 + 본문 길이 > S`이면 레코드가 파일 끝을 넘습니다. 남은 바이트로 필드를 읽어 봅니다. 남은 바이트 안에서 모든 필드가 다 읽히면 길이 칸이 내용과 맞지 않는 것이므로 `손상`입니다. 다 읽히지 않으면 `잘림`입니다. INSERT는 레코드를 write 한 번으로 붙이므로, 잘린 끝은 진짜 레코드의 앞부분입니다(`docs/prd/CJG.md` 101줄).
5. 본문을 읽습니다. 필드가 본문 길이를 정확히 다 써야 합니다. 남거나 모자라면 `손상`입니다.
6. `id`는 앞 레코드의 `id`보다 커야 하고, 첫 `id`는 1 이상이어야 합니다. 아니면 `손상`입니다. 파일은 덧붙이기만 하고 ID는 오름차순으로 나가므로 비교 한 번이면 됩니다.
7. `o = o + 4 + 본문 길이`로 옮기고 계속합니다.

`잘림`이나 `손상`이 나오면 `engine_create`가 실패합니다. 파일은 바꾸지 않습니다. 메시지에는 파일 이름, 바이트 위치, 레코드 번호, 종류를 적습니다.

```text
data/users.tbl: 1520번째 바이트의 레코드(38번째)가 깨졌습니다: 잘림 (레코드 중간에서 파일이 끝남)
```

CLI는 종료 코드 1로 끝나고, 서버는 뜨지 않습니다.

## 기본선에는 CRC를 넣지 않음

- CRC는 파일을 자동으로 고칠 때 쓸모가 있습니다. 기본선은 멈추고 알리기만 합니다.
- CJG 시험 엔진에서 CRC 계산이 SCAN 시간의 약 60%였습니다(`docs/prd/CJG.md` 104줄). CRC를 넣으면 INDEX와 SCAN 비교에 체크섬 비용이 섞입니다.
- LMH 초안은 체크섬 손상 감지를 범위 밖으로 두었습니다(`docs/PRD.md` 207줄).

알려진 한계: 길이 칸은 맞고 TEXT 값 안의 바이트만 바뀌면 찾지 못합니다. `README.md`의 "알려진 한계"에 적습니다. 자동 복구를 차별점으로 넣을 때 CRC도 같이 넣습니다.

## 테스트로 확인할 것

- 빈 테이블 파일은 정상이고 다음 ID는 1입니다.
- 마지막 길이 칸 중간(1~3바이트)에서 끝난 파일은 `잘림`으로 시작이 멈춥니다.
- 마지막 본문 중간에서 끝난 파일은 `잘림`으로 시작이 멈춥니다.
- 길이 칸이 파일 끝을 넘는 중간 레코드는 `잘림`이 아니라 `손상`입니다.
- 길이가 0인 레코드는 `손상`입니다. 0으로 채워진 끝이 이 경우입니다.
- 필드가 본문 길이보다 적게 또는 많게 쓰는 레코드는 `손상`입니다.
- 앞 레코드보다 작거나 같은 `id`는 `손상`입니다.
- 실패한 뒤 파일 크기와 내용이 그대로입니다.
